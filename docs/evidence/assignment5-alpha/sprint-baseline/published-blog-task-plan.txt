# --- Governing conventions quoted in the blog ---
#
# Branch strategy: main holds the stable phase baseline; sprint/alpha is the
# Alpha Sprint integration branch. Task branches use feat/<issue-id>-<short-slug>
# or fix/<issue-id>-<short-slug> and merge back to sprint/alpha via Pull Request
# after self-check and peer review.
#
# Commit format: <type>(<scope>): <subject> (#<issue>) with allowed types feat,
# fix, docs, style, refactor, test, chore. Every development commit during the
# sprint must reference its corresponding GitHub Issue number.
#
# Backend standards: Python 3.13 / FastAPI / SQLAlchemy 2 / MySQL 8.4. Passwords
# hashed with salted PBKDF2-HMAC-SHA256 (600,000 iterations); bearer tokens stored
# as SHA-256 digests. Alembic migrations via `alembic upgrade head`. ruff
# line-length = 100.
#
# Workspace: pnpm@11.24.0 workspace commands. All shared DTOs and enums must be
# imported from @codestrike/contracts (packages/api-contracts), never duplicated
# locally. Zero TypeScript errors allowed before commit: `pnpm type-check` must pass.
